# 申请书组件开发指南

欢迎来到要素式诉辩状生成平台的申请书组件开发指南！本文档旨在帮助开发者快速、规范地创建新的申请书表单页面。

## 快速开始：创建一个新的申请书页面

假设我们需要创建一个新的"不予执行仲裁裁决申请书"。

### 第1步：创建表单页面文件

在 `src/forms/application/` 目录下创建一个新文件：`NonEnforcementOfArbitrationFormPage.tsx`。

### 第2步：复制基础模板

## 核心组件详解

### 1. `<FormPageLayout>`

这是所有表单页面的根布局组件，它封装了 `react-hook-form` 的 `FormProvider` 和所有通用功能。

| Prop | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `title` | `string` | 是 | 显示在页面顶部的完整标题。 |
| `formId` | `string` | 是 | 一个全局唯一的ID，用于本地草稿的存储和读取。建议格式：`application_本表单名字（英文）`。 |
| `docType` | `"申请书"` | 是 | 告诉布局当前是哪种文书，影响文档生成逻辑。 |
| `onPreviewData` | `(data: any) => any` | 是 | 一个函数，负责将 `react-hook-form` 的原始数据 (`data`) 转换成最终生成Word文档所需的 `final_data` 格式。 |
| `fixedFormValues` | `object` | 否 | 一个对象，用于为表单中的某些字段提供不可更改的默认值。 |
| `instructions` | `string` | 否 | HTML字符串，用于显示表单填写说明和注意事项。 |
| `leftPanel` / `rightPanel` | `React.ReactNode` | 否 | 自定义左右侧边栏的内容。（通常不需要特别设置） |

### 2. `<FormSectionCard>`

一个带标题和边框的卡片容器，用于将表单内容按逻辑块（如"申请人"、"申请事项"）进行分组。

| Prop | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `title` | `string` | 是 | 显示在卡片顶部的标题。 |
| `children`| `React.ReactNode`| 是 | 卡片内部的内容。 |

### 3. `<PartyList>`

用于处理当事人（申请人、被执行人、其他当事人）信息。它内置了 `useFieldArray`，允许用户动态添加多个当事人。

| Prop | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `path` | `string` | 是 | 当事人数据在表单中的存储路径，例如 `applicant_natural`。 |
| `title`| `string` | 是 | 显示在该列表区域的标题，例如"自然人"。 |
| `partyType` | `"natural"` \| `"legal"` | 是 | 决定了是渲染自然人表单还是法人表单。 |
| `specialType` | `string` | 否 | 特殊类型标识，用于区分不同表单的当事人角色。 |

### 4. `<AgentList>`

用于处理委托代理人信息。

| Prop | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `path` | `string` | 是 | 代理人数据在表单中的存储路径，通常为 `agents`。 |

### 5. `<QuestionTable>`

用于快速渲染要素式问答表格的核心组件。

| Prop | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `config`| `QuestionConfig[]` | 是 | 一个问题配置对象数组，`QuestionTable` 会根据这个配置来渲染每一行。 |

## QuestionConfig 配置详解

`QuestionConfig` 是用于定义表单中每个问题的配置对象，支持多种类型：

### 1. `textarea` 类型

最简单的文本域输入，适用于长文本输入。

```typescript
{
  type: "textarea",
  path: "docInfo.issuingBody",
  title: "文书作出机构"
}
```

### 2. `optimizationContext` 类型

支持AI优化的文本域，用户可以请求AI帮助优化内容。适用于大部分需要用户填写长文本内容，但不适用于具体事实性内容（如案号、前置法律文书名称等）。

```typescript
{
  type: "optimizationContext",
  path: "request.main",
  title: "申请请求",
  optimizationContext: "用户申请不予执行特定法律文书的请求"
}
```

### 3. `custom` 类型（重要）

自定义类型允许您完全控制该行的渲染内容和格式化方式。

```typescript
{
  type: "custom",
  path: "docInfo.type",
  title: "法律文书类型",
  children: () => (
    <FormField
      path="docInfo.type"
      type="radio_detail"
      options={[
        { value: "仲裁裁决", label: "仲裁裁决" },
        { value: "仲裁调解书", label: "仲裁调解书" },
        { value: "公证机关依法赋予强制执行效力的债权文书", label: "公证机关依法赋予强制执行效力的债权文书" },
        { value: "其他法律文书", label: "其他法律文书" },
      ]}
      triggerValue="其他法律文书"
      detailsLabel="类型"
      placeholder="请填写具体文书类型"
    />
  ),
  formatter: (formData) => {
    const data = getValueFromPath(formData, "docInfo.type") || {};
    const choice = data.choice;
    const details = data.details || '';

    // 定义选项列表，与表单中的options保持一致
    const options = [
      { value: "仲裁裁决", label: "仲裁裁决" },
      { value: "仲裁调解书", label: "仲裁调解书" },
      { value: "公证机关依法赋予强制执行效力的债权文书", label: "公证机关依法赋予强制执行效力的债权文书" },
      { value: "其他法律文书", label: "其他法律文书" },
    ];

    // 为每个选项生成带勾选标记的文本
    const formattedOptions = options.map(option => {
      const checked = choice === option.value ? '☑' : '☐';
      let line = `${option.label}${checked}`;
      // 如果是"其他法律文书"且被选中，则添加详细内容
      if (option.value === "其他法律文书" && choice === option.value && details) {
        line += ` ${details}`;
      }
      return line;
    });

    // 返回格式化的文本，每项占一行
    return formattedOptions.join('\n');
  },
}
```

#### `custom` 类型属性说明：

| 属性 | 类型 | 必需 | 说明 |
| :--- | :--- | :--- | :--- |
| `type` | `"custom"` | 是 | 指定为自定义类型 |
| `path` | `string` | 是 | 数据存储路径 |
| `title` | `string` | 是 | 问题标题 |
| `children` | `() => React.ReactNode` | 是 | 渲染自定义内容的函数 |
| `formatter` | `(formData: any) => string` | 是 | 将表单数据格式化为最终文档文本的函数 |

### 4. 使用 `<FormField>` 组件

在 `custom` 类型的 `children` 函数中，您可以使用 `<FormField>` 组件创建各种输入控件。

#### 支持的字段类型：

| 类型 | 说明 |
| :--- | :--- |
| `text` | 普通文本输入框 |
| `textarea` | 多行文本框 |
| `number` | 数字输入框 |
| `date` | 日期选择器 |
| `radio` | 单选按钮组 |
| `checkbox` | 复选框 |
| `radio_detail` | 带详情的单选按钮组 |
| `checkboxGroup` | 复选框组 |
| `money` | 金额输入框 |
| `optimizable-textarea` | 可AI优化的文本区域 |

#### 常用属性：

| 属性 | 类型 | 说明 |
| :--- | :--- | :--- |
| `path` | `string` | 表单字段在表单数据中的路径 |
| `type` | `string` | 字段类型 |
| `label` | `string` | 字段标签 |
| `placeholder` | `string` | 占位符文本 |
| `options` | `Array<{value: string, label: string}>` | 选项列表，用于radio、select等 |
| `frontLabel` | `string` | 前置标签 |
| `endLabel` | `string` | 后置标签 |
| `triggerValue` | `string` | 触发详情显示的radio值（用于radio_detail类型） |
| `detailsLabel` | `string` | 详情输入框标签（用于radio_detail类型） |

#### 示例：

```typescript
// 简单文本输入
<FormField path="field1" type="text" frontLabel="姓名" />

// 金额输入
<FormField path="amount" type="money" frontLabel="金额" />

// 日期输入
<FormField path="date" type="date" frontLabel="日期" />

// 单选按钮组
<FormField 
  path="choice" 
  type="radio" 
  options={[
    { value: "yes", label: "是" },
    { value: "no", label: "否" }
  ]} 
/>

// 带详情的单选按钮组
<FormField
  path="type"
  type="radio_detail"
  options={[
    { value: "type1", label: "类型1" },
    { value: "type2", label: "类型2" },
    { value: "other", label: "其他" },
  ]}
  triggerValue="other"
  detailsLabel="其他类型说明"
/>
```

## 数据格式化

申请书组件需要将表单数据格式化为Word文档模板所需的格式。主要通过 `processFormDataForPreview` 函数实现。

### 1. 格式化当事人信息

使用 `formatPartiesForDocx` 和 `formatAgentsForDocx` 工具函数：

```typescript
const applicantBlueprints = [
  {
    path: "applicant_natural",
    roleText: `申请人(自然人)`,
    type: "natural" as const,
    specialType: DOC_TYPE
  },
  {
    path: "applicant_legal",
    roleText: `申请人(法人/非法人组织)`,
    type: "legal" as const,
    specialType: DOC_TYPE
  },
];

const partyInfo = [
  ...formatPartiesForDocx(data, applicantBlueprints),
  ...formatAgentsForDocx(data),
];
```

### 2. 格式化表单要素

使用 `formatFormData` 函数和配置中的 `formatter`：

```typescript
const documentInfo_formatted = formatFormData(
  "documentInfo",  // section名称
  data,            // 表单数据
  documentInfoConfig // 配置数组
);
```

对于 `custom` 类型，需要在配置中提供 `formatter` 函数：

```typescript
formatter: (data) => {
  // 从data中提取相关值
  const value = data?.some?.path || "";
  
  // 格式化为适合Word文档的文本
  return `格式化后的文本内容`;
}
```

## 注册新页面

### 1. 注册表单路由 (`FormContainer.tsx`)

在 `src/pages/FormContainer.tsx` 的 `formMap` 对象中，添加新表单的映射。

```typescript
// src/pages/FormContainer.tsx
const formMap: { [key: string]: LazyComponent } = {
    // ... 其他表单
    'application-non-enforcement': lazy(() => import('../forms/application/NonEnforcementOfArbitrationFormPage')),
};
```

### 2. 注册模板信息 (`template_database.py`)

在后端的 `app/templates/template_database.py` 中，为新表单添加一条记录，以便用户可以在模板选择页面看到它。

```python
# app/templates/template_database.py
"application": {
    # ... 其他模板
    {"id": "non-enforcement", "name": "不予执行申请书", "path": "/application/non-enforcement",
        "description": "适用于申请不予执行仲裁裁决、仲裁调解书、公证债权文书等情形。", "disabled": False},
},
```

## 最佳实践

1. **命名规范**：
   - 文件名使用 PascalCase，以 FormPage 结尾，如 `NonEnforcementOfArbitrationFormPage.tsx`
   - 表单ID使用小写字母和下划线，如 `application_non_enforcement_arbitration`

2. **代码组织**：
   - 将常量和配置放在文件顶部
   - 按功能将代码分块并添加注释
   - 使用有意义的变量名和函数名

3. **数据格式化**：
   - 为每个 `custom` 类型提供 `formatter` 函数
   - 确保格式化后的文本符合Word模板要求
   - 使用工具函数处理通用格式化任务

4. **用户体验**：
   - 提供清晰的填写说明
   - 合理组织表单结构
   - 使用适当的输入控件类型
